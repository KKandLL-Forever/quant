> _**Abstract**_ **—Autonomous crypto trading systems often spend most of their design effort on finding entries, while exits are left to fixed rules that are rarely tested in a systematic way. This paper examines whether better stop-loss and take-profit settings can improve the performance of an autonomous trading agent swarm. Using more than 900 historical trades, we replay each trade under many alternative exit policies and compare results against the existing production setup. The study finds that exit design matters meaningfully: stronger configurations improve risk-adjusted performance and generally favor tighter loss limits, earlier profit capture, and closer trailing protection. The paper also discusses a key evaluation challenge: a purely chronological split was initially used, but the newest trades fell into an unusual war-driven market period that sharply distorted test results. To reduce the influence of that single episode, the main comparison was run on randomized data, with the drawbacks of doing so acknowledged explicitly. Overall, the paper presents a practical framework for tuning exit logic in a more disciplined and transparent way.** 
> 
> _**Index Terms**_ **—autonomous trading, agent swarm, exit strategy calibration, stop-loss, trailing stop, take-profit, counterfactual simulation

## Methodology

The trading strategy described is not a traditional signal-based directional strategy (momentum, mean reversion, etc.) but rather a systematic exit‑overlay framework designed for an autonomous trading agent swarm. The core idea is to improve risk‑adjusted performance by rigorously calibrating the stop‑loss, take‑profit, trailing‑stop, stale‑close, and circuit‑breaker rules that are applied uniformly to all positions generated by a diverse set of entry agents. The agents themselves monitor market state and produce candidate trades every ~15 minutes using a “top‑trader” signal; their exact logic is undisclosed and treated as a black‑box entry source. The exit policy is the sole focus: once a position is opened, a shared execution layer applies the same exit logic regardless of which agent originated the trade, making the calibration a portfolio‑level optimisation problem over historical trades.

**Step‑by‑step exit process**  
For each trade, the simulated price path is replayed, and the following rules are checked in chronological order:

1. **Fixed‑percentage stop‑loss** – If price declines by *SL%* from entry, the entire position is closed. The baseline used 25%, but the best configuration uses 10%.
2. **Trailing stop** – Once price rises by a *trailing‑activation* threshold (TA%, e.g., 3%), a trailing stop is activated. It dynamically follows the highest price achieved since activation, keeping a *trailing‑distance* (TD%, e.g., 5%) below that peak. If price declines to this level, the position is closed.
3. **Partial take‑profit** – When price reaches a *partial‑take‑profit threshold* (PTP%, e.g., 10%), a fraction *PF* (e.g., 75%) of the position is closed. The remainder stays open and continues to be governed by the trailing stop and any other open rules.
4. **Stale‑close** – If the trade remains open beyond a maximum number of hours (e.g., 48 h), it is automatically closed.
5. **ATR‑based overlays** – In a refined stage, fixed‑percentage stop‑loss and take‑profit levels are replaced or supplemented by volatility‑scaled values. An ATR stop multiplier (1.0×) sets the stop distance from entry as *K × Average True Range*; an ATR take‑profit multiplier (2.0×) sets a profit target similarly. These levels adapt to recent market volatility.
6. **Circuit‑breaker** – After *N* consecutive losing trades (e.g., 2 losses), all subsequent position sizes are reduced by a factor *CB* (e.g., 0.25) to limit drawdowns until a win resets the count.

The final recommended production configuration is: **SL = 10%, TA = 3%, TD = 5%, PTP = 10%, PF = 75%, stale‑close = 48 h**, with **ATR stop = 1.0×, ATR take‑profit = 2.0×**, and a **circuit‑breaker reducing position size to 25% after 2 consecutive losses**.
